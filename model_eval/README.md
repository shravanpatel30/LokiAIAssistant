# Model comparison kit

Tests local models on the kind of work Loki does, and writes a side-by-side report.

**24 tests:**

- **9 image tests** (vision models only):
  - 4 equations → LaTeX (Gaussian integral, Schrödinger, transmon Hamiltonian, partition function)
  - a resonator plot (read f₀ and FWHM)
  - a T1 decay plot (estimate T1)
  - a data table (Ohm's law → average R)
  - an RC circuit (filter type and cutoff)
  - a handwritten circuit problem (parallel resistors + a sign convention; answer −1 mA). 8B vision models get this wrong; it's here to test bigger models when you upgrade
- **15 reasoning tests:**
  - classic logic traps
  - known LLM weak spots ("r"s in *strawberry*, 9.11 vs 9.9)
  - probability (Monty Hall, two children)
  - physics calculations (projectile, muon time dilation, Balmer line)
  - qubit questions (π-pulse length, Pauli expectation values)

Every image except the handwritten circuit (yours) is generated by `make_images.py`, so the right answers are known exactly.

## Run

Ollama must be running. From the project folder:

```bash
ollama pull qwen3-vl:8b
python model_eval/run_eval.py
```

Then open `model_eval/report.html` in your browser.

The default compares `qwen3:8b`, `qwen3:8b+think` and `qwen3-vl:8b` (`+think` means thinking mode on). Each model is unloaded before the next one loads, so they don't fight over VRAM.

```bash
python model_eval/run_eval.py --only images                  # just the image tests
python model_eval/run_eval.py --only reasoning               # just the text tests
python model_eval/run_eval.py --ids muon,rabi,plot_t1        # specific tests
python model_eval/run_eval.py --models "qwen3-vl:8b-instruct,qwen3-vl:8b-thinking"
python model_eval/run_eval.py --ctx 8192                     # bigger context window (uses more VRAM)
python model_eval/run_eval.py --rescore                      # re-check results.json, rebuild report — no model calls
```

**"⚠ Cut off"** means the model filled its context window before it finished answering. That happens most with thinking models, and with images, since an image takes about 1,000 tokens of the window. Try `--ctx 8192`, or use a non-thinking (instruct) model.

Thinking runs are slow. The full default run can take 15–30 minutes, so try `--only images` first.

## Reading the report

- **✓** means the answer contains the expected value. **?** means it didn't match the pattern. The auto-check is a hint, not a grade, so read the answers yourself: a model can be right in an unexpected format, or contain the right number for the wrong reason.
- For equation tests, each model's LaTeX is rendered next to the original image, so you can spot a wrong subscript at a glance.
- **Time:** the first answer for each model includes loading it into VRAM. The summary table uses the median, so that load time doesn't skew it.

## Adding your own tests

Put an image in `images/` (a screenshot from one of your papers works well) and add an entry to `questions.json`:

```json
{"id": "my_eq", "category": "Equation → LaTeX", "image": "my_eq.png",
 "prompt": "Convert the equation in this image to LaTeX. Output only the LaTeX code.",
 "expected": "the LaTeX you expect", "checks": []}
```

`checks` is a list of regex patterns that must all appear in the answer. Leave it empty to judge by eye. Starting the category with `Equation` turns on rendered-LaTeX comparison.
